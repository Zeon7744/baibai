# Vibe Coding 工作流

## 核心理念

Vibe Coding 是由 Andrej Karpathy（OpenAI联合创始人）于 2025年2月 提出的 AI 驱动编程范式。

核心转变：
- 从"写代码" → "描述意图"
- 从"调试语法" → "把控体验"
- 从"逐行审查" → "看效果迭代"

---

## 标准工作流

### 四步循环

```
┌─────────────┐     ┌─────────────┐
│  1. 描述    │ ──▶ │  2. 生成    │
│  (Describe) │     │  (Generate) │
└─────────────┘     └─────────────┘
       ▲                   │
       │                   ▼
       │         ┌─────────────┐
       │         │  3. 验证    │
       │         │  (Verify)   │
       │         └─────────────┘
       │                   │
       └───────────────────┘
                    反馈
```

---

## 详细步骤

### Step 1: 描述（Describe）

用自然语言清晰描述需求，包含：
- 功能需求（做什么）
- 技术栈（用什么）
- 风格要求（什么样）
- 约束条件（边界在哪）

**示例：**
> "做一个待办清单网页，支持增删改查、标记完成，界面极简，适配移动端，数据存在 localStorage"

---

### Step 2: 生成（Generate）

AI 直接输出完整、可运行的代码包：
- HTML/CSS/JS 文件
- 配置文件
- 项目结构

**关键：不要逐行审查代码**，直接运行看效果。

---

### Step 3: 验证（Verify）

运行代码，检查：
- 功能是否实现
- 体验是否符合预期（"氛围对不对"）
- 有无明显报错

**核心原则：看效果，不看代码。**

---

### Step 4: 反馈（Feedback）

遇到问题，用自然语言描述：
- 复制错误信息
- 截图视觉问题
- 说明期望效果

**示例：**
> "按钮颜色改成蓝色，添加分页，修复删除时的报错，优化移动端布局"

---

### Step 5: 迭代（Iterate）

重复 Step 2-4，直到效果达标：
- 不需要一次完美
- 优先"可运行"，再优化
- 每次迭代解决一个具体问题

---

## 进阶技巧

### 记忆银行（Memory Bank）

```
project/
├── memory-bank/
│   ├── design.md        # 产品需求文档
│   ├── tech-stack.md    # 技术栈选择
│   ├── plan.md          # 实现计划
│   └── progress.md      # 进度追踪
```

每次新建项目时，先创建这些文档，让 AI 有上下文。

---

### AGENTS.md 规则

在项目根目录创建 `AGENTS.md`，定义 AI 行为规则：
```markdown
# 项目规则
- 所有代码模块化，禁止单文件超过 200 行
- 样式使用 TailwindCSS 类名
- 错误处理统一使用 try-catch
```

---

### 断点续传

使用 `/new` 或 `/clear` 开始新对话：
- 新对话更干净
- 旧对话上下文干扰

## 注意事项

### 适用场景
- ✅ 快速原型
- ✅ 个人工具
- ✅ 小型应用
- ❌ 大型商业系统
- ❌ 高安全要求项目

### 核心局限
- 代码质量依赖 AI 输出
- 复杂架构需要人工介入
- 性能优化需手动调整
